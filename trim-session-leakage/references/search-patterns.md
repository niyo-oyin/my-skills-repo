# 検索パターン

[類型](../SKILL.md#類型)ごとに探りを入れるためのパターンである。
どのヒットも、意味で判断する必要がある。
パターンは、意図的に広めに一致するように作ってある。
それでも、性質上、一致しない漏れが出る。
パターンにかからない漏れが必ずあるので、スコープの中で文章の密度が高い場所をパターンなしで読む作業と組み合わせる。

## 実行の規則

- `--hidden --glob '!.git/**'` を付ける。
  ripgrep は、名前がドットで始まるディレクトリを既定で読み飛ばす。
  エージェント向けの指示や決定記録は、`.agents/` や `.github/` のような場所に置かれていることが多い。
- 除外指定は最後に置く。
  あとに続く包含指定で、除外したファイルが対象に戻らないようにするためである。
  たとえば `--glob '!vendor/**' --glob '!node_modules/**'` のように書く。
  凍結された記録、記録されたフィクスチャ、スナップショットのディレクトリがスコープに入る場合は、それらも除外する。
- このスキル自身のファイルは、判定の基準を確かめる材料として、漏れた言い回しを引用している。
  スコープに入る場合は、`--glob '!**/trim-session-leakage/**'` で除外する。
- 日本語には単語の区切りがないので、文章用のパターンは、助詞や語尾まで含めて語句を区切っている。
  「以前は」は「以前は配列を返していた」に一致し、「以前の値と比較する」には一致しない。
- ヒットが 0 件のパターンは、既知の漏れの例に一致することを確かめるまで、何の証明にもならない。
  ヒットが多いパターンは、紛らわしいが漏れではない例に一致しないことを確かめるまで、何の証明にもならない。
  対象全体での結果を信用する前に、[確認用の例文](#確認用の例文)で両方を確かめる。
- シェルによっては、コマンドラインに直接書いた日本語や `§` などの非 ASCII 文字が文字化けする。
  パターンが一致しないときは、パターンを UTF-8 のファイルに書き、`rg -f <ファイル>` で渡す。

## パターン

末尾の `...` は、スコープと除外指定に置き換える。

```sh
# 1. 消えた設計セッションへの引用
rg -n --hidden '[（(](決定|判断|監査|指摘|論点)\s*[A-Z]?-?\d|(設計|計画|方針)(書|メモ|案|台帳)?\s*[（(]?(v\d+\s*)?§|(フェーズ|ステージ)\s*\d|[（(][A-Z]\s?案|設計台帳|(設計|検討|作業)メモ' ...
rg -n --hidden '§\s*\d' ...

# 2. スタックと PR の視点
rg -n --hidden '(この|本|今回の|当該)\s*(PR|プルリク(エスト)?|ブランチ|コミット|スタック)\s*(で|では|にて|により|から|は|が|の)|(後続|次|別|以降|前|直前|先行)の\s*(PR|プルリク(エスト)?|コミット)\s*(で|では|にて|により|が|は|に)|今回の(変更|修正|対応|実装|整理|リファクタ(リング)?)(で|では|により|にて)' ...

# 3. 変更の語り
rg -n --hidden '以前は|かつては|従来は|これまでは|元々は|もともとは|当初は|旧(実装|仕様|版|方式)|古い(実装|仕様|方式|コード)|もう[^。\n]{0,15}(ない|ません)(。|$|が、|ので|ため)|もはや|(では|し|され|でき|使われ|呼ばれ|まれ)なくなった|(削除|撤去|除去|廃止)(した|された|済み)(。|$|ため|ので|が、)|に(変更|改名|リネーム|移動|置き換え|移行)(した|された|しました|済み)|(修正|対応)済み' ...

# 3. 版の刻印
rg -n --hidden '今回は|現時点では|現状(は|では)|今のところ|いまのところ|今は|今では|現在は|v\d+\s*(では|の時点|時点)|初版では|現バージョンでは|ロードマップ' ...

# 4. レビューのやり取り
rg -n --hidden 'レビュー(で|にて|の結果|指摘|コメント|を受け|により|済み)|レビュ[アワ]ー|査読者?(が|に|の|から)|指摘(を受け|により|があった|された|の通り|のとおり)|ご指摘|却下(され|した|。|：|:)|第\s*\d+\s*(版|稿|ラウンド)|\d+\s*(回目|巡目)の(レビュー|指摘)|(議論|相談|検討)の結果|合意(した|済み|の上|のうえ)' ...

# 5. レビュアーに向けた正当化
rg -n --hidden '(ので|ため|から)、?\s*(安全|問題な|問題はな|大丈夫)|安全(である|です|だ|なはず)|問題(ない|ありません|はない|なし)|大丈夫|単に[^。\n]{0,30}(だけ|にすぎない|に過ぎない)|正しい(のは|はず|ことを確認)|心配(ない|いらない|は不要|無用)' ...

# 6. 言い直しと導出の書き起こし
rg -n --hidden 'まず[^。\n]{0,50}(次に|その後|続いて|それから|最後に)|^\s*(//|#|\*|--|;)\s*(まず|次に|その後|続いて|それから|最後に)[、 は]|この(テスト|関数|メソッド|ループ)は、?[^。\n]{0,40}、[^。\n]{0,40}、' ...

# 7. ぼかした表現と計画の名残
rg -n --hidden 'たぶん|多分|おそらく|恐らく|かもしれ(ない|ません)|(はず|だろう|でしょう|と思う|と思われる|と思います)(。|$|が、|だが|です|である|だ)|とりあえず|ひとまず|当面|暫定|念のため|(あと|後)で(直す|対応|修正|検討|見直|考え|整理|実装)|将来的に|いずれ[、は]|要(検討|確認|調査)|検討中' ...

# 8. 作業言語の名残。英語で書く決まりの場所だけを対象にする
rg -n --hidden '[\p{Hiragana}\p{Katakana}\p{Han}]|-{4,} .{1,30} -{4,}' --glob '<英語で書く決まりのファイル>' ...
```

## 確認用の例文

パターンごとに、一致するはずの行と、一致しないはずの行を一つずつ示す。
対象のプロジェクトで実際に見つけた例があれば、そちらを優先して使う。

| パターン | 一致するはずの行 | 一致しないはずの行 |
|---|---|---|
| 1 | 「表示中のカタログに対して解決する（決定 21）。」 | 「決定木を作って入力を分類する。」 |
| 2 | 「この PR で、ページ分割を追加する。」 | 「このプロジェクトでは pnpm を使う。」 |
| 3（語り） | 「以前は配列を返していた。」 | 「以前の値と比較して、差分だけを送る。」 |
| 3（刻印） | 「今回は描画を同期で行う。」 | 「今回分の集計を次の実行に渡す。」 |
| 4 | 「レビューで却下：仕様のキャッシュ。」 | 「却下の理由を呼び出し側に返す。」 |
| 5 | 「SDK が構築するので、問題ない。」 | 「問題を検出したら例外を投げる。」 |
| 6 | 「まず正規化し、次に切り詰める。」 | 「まず、先頭の要素を返す。」 |
| 7 | 「これで足りるはずだ。」 | 「十分な容量を確保する。」 |
| 8 | "runs on the client 側" | 表の区切り行 `\| --- \| --- \|` |

## 既知の偽陽性

次のものは、ヒットしても漏れではない。
繰り返し現れるので、あらかじめ知っておく。

- **実行時の新旧と前後**：「古い接続は、新しい接続が受け付けを始める前に、処理中のリクエストを最後まで処理する」や「前回の実行の結果」は、実行時のオブジェクトと状態を指している。
  リポジトリの状態を指しているのではない。
- **実行時の状態としての「削除された」「変更された」**：「値が 0 に変更されたら再計算する」は、振る舞いを述べている。
  変更の語りとは、コードがどう変わったかを語ることである。
- **開発プロセスの文書の中の PR とレビュー**：PR の書き方、レビューの手順、テンプレートなど、プロセスそのものを説明する文書は、「PR」や「レビュー」と書いてよい。
  禁止しているのは、コードについての文書が、特定の一つの PR の視点を取ることである。
- **手順の中の「まず」「次に」**：読み手が行う操作の順序を示す手順は、制御フローの語りではない。
  類型 6 が対象にしているのは、コードがすでに示している処理の順序を、言葉で言い直すことである。
- **プロトコルやパスの一部である `v1`**：`/v1/chat` のようなエンドポイントや通信形式の名前は識別子であり、版の刻印ではない。
- **コミット済みの所有者がある `§N`**：外部の規格（RFC 9110 §10.1.5）と、節番号を自分で管理しているコミット済みの文書は、節で引用してよい。
- **実行時の「今日」「現在」と記録されたタイムスタンプ**：現在の日付を尋ねるプロンプトやテストは、実行時の時刻を使っている。
  記録された CLI の出力は、元の言い回しのまま保つ。
  モデルやユーザーに届く文言を編集するには、まず、その振る舞いを固定する証拠が必要である。
- **実行時の動作としての「一時的に」**：「一時的に停止して、あとで再開できる」は、動作を述べている。
  パターン 7 には含まれていないが、ぼかした表現の検索語を広げると現れる。
- **「検討した代替案」の節**：決定記録のこの節にある「却下」は、認められた場所にあり、レビューのやり取りではない。
- **経緯を書く場所**：変更履歴、決定記録の経緯の節、ポストモーテムは、変更の語りを書く場所である。
  そこでの類型 3 のヒットは、ほとんどが正当なものである。
