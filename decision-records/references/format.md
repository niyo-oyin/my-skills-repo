# 既定の形式

この形式を使うのは、決定記録を新しく導入するときと、プロジェクトの規約が定めていない点を補うときだけである。
プロジェクトに規約があれば、それに従う。

## 置き場所とファイル名

- 記録は `docs/decisions/` に置き、規約はそのディレクトリの `README.md` に書く。
- ファイル名は `YYYY-MM-DD-<動詞句>.md` とする。
  例は `2026-06-15-use-sqlite-for-test-database.md` と `2026-07-01-keep-error-text-unchanged.md` である。
- 日付は、記録を作成した日である。
  作成後は変更しない。
- 動詞句は英小文字とハイフンで書き、決定を現在形で述べる。
  プロジェクトにファイル名の規約があれば、それに従う。
- 同じ日付の記録を複数作ってよい。
  連番ではなく日付を使うのは、並行するブランチの間で衝突しないからである。

## 言語と節の名前

記録は、プロジェクトのドキュメントと同じ言語で書く。
節の名前は次のとおりとする。

| 日本語 | 英語 |
|---|---|
| 背景と課題 | Context and Problem Statement |
| 決定 | Decision |
| 検討した代替案 | Alternatives Considered |
| 補足（任意） | More Information |

タイトル（1 行目の見出し）は、決定そのものを言い切る形で書く。
「テスト用データベースに SQLite を使う」はタイトルになるが、「テスト用データベースの評価」はタイトルにならない。

## 状態と索引

- 状態のフィールドや frontmatter は入れない。
  デフォルトブランチにある記録が、承認済みの記録である。
  提案中の記録は、マージされていないブランチか PR の中にある。
- 索引は作らない。
  ファイル名が日付と決定を表しているので、ディレクトリの一覧が索引の役割を果たす。
  索引を別に持つと同じ情報を二重に管理することになり、無関係な記録の追加どうしが一つのファイルで衝突する。
- 記録が増えて探しにくくなったら、レイヤーや領域ごとのサブディレクトリに分け、分類の方針を README に書く。

## 注記と追記

承認済みの記録に足してよい注記は、タイトルの直後に、1 行の引用ブロックとして書く。
日付は、注記を足した日である。

```markdown
# テスト用データベースに SQLite を使う

> **置き換え済み**（2026-09-02）：[テスト用データベースに PostgreSQL コンテナを使う](2026-09-02-use-postgres-container-for-test-database.md)
```

注記は三種類ある。
波括弧の部分を置き換えて使う。

```markdown
> **置き換え済み**（{日付}）：[{新しい記録のタイトル}]({ファイル名})
> **一部置き換え済み**（{日付}）：{置き換えられた範囲}は[{新しい記録のタイトル}]({ファイル名})に従う。
> **廃止**（{日付}）：{適用されなくなった理由}
```

あとから分かったことは、「補足」の末尾に、日付を付けた箇条書きで追記する。

```markdown
- 2026-10-01：SQL 方言の違いによるバグは 3 か月で 1 件であり、見直しの条件には達していない。
```

## 記録のテンプレート

波括弧の中の文章は説明なので、すべて置き換える。
「補足」は任意なので、書くことがなければ節ごと削除する。

```markdown
# {決定そのものを言い切るタイトル}

## 背景と課題

{何が問題か、なぜ今決めるのか、どのような制約があるかを、元の会話を知らない読み手にも分かるように書く}

## 決定

{何を選んだか、なぜ選んだか、適用する範囲と対象外の事項、この選択で受け入れたトレードオフを書く}

## 検討した代替案

- **{代替案 1}**：{利点と欠点、選ばなかった理由を書く}
- **{代替案 2}**：{利点と欠点、選ばなかった理由を書く}

## 補足

{関連する記録、PR、issue、決定を見直す条件を書く}
```

説明が長くなる代替案は、箇条書きにせず、小見出しを立ててもよい。

## README のテンプレート

`{置き場所}` は、実際のディレクトリに置き換える。

```markdown
# 決定記録（ADR）

決定記録は、システムの作り方や動かし方についての決定を、その背景、理由、退けた代替案と一緒に残す文書である。

## 規約

- 置き場所：`{置き場所}`
- ファイル名：`YYYY-MM-DD-<動詞句>.md`（日付は記録を作成した日）
- 節：背景と課題、決定、検討した代替案、補足（任意）
- 記録には状態のフィールドも frontmatter もなく、デフォルトブランチにある記録が承認済みの記録である。
- 実装計画と検証手順は issue か PR に書き、記録からリンクする。

## 運用

- 構成、依存関係、インフラ、公開 API、データ形式、運用方針を変更する前に、関係する記録を読む。
- 新しい決定は、その記録を PR に含めて提案する。
- 承認済みの記録の決定、理由、代替案は書き換えない。
- 決定を覆すときは新しい記録を書き、古い記録のタイトルの直後に置き換え済みの注記を足して、二つの記録を相互にリンクする。
```
