# gemini-api CLI

`gemini-api` は Gemini API をシェルから呼ぶためのステートレスな CLI。プロンプトやファイルを渡すと、テキストは stdout に、メディアはファイルとして返ってくる。ホストエージェントが作業を組み立て、足りない能力を Gemini から借りる、という使い方をする。

向いている場面:

- **文章を見てもらう**: 日本語の文章のレビュー、校正、推敲、言い換え。自分で書いた文章は自分では粗が見えにくいので、別モデルの目が効く
- **セカンドオピニオン**: 設計、実装方針、コード、デザイン案に対する別視点の意見
- **ファイルの中身を知る**: PDF、画像、音声、動画、CSV、YouTube URL についての質問
- **素材を作る**: 画像、ナレーション、BGM、動画
- **録音を文字にする**: 文字起こし、字幕
- **調査を任せる**: 複数ステップの調査をマネージドエージェントにバックグラウンドで委任

## 前提

API キーが必要(`GEMINI_API_KEY` 環境変数、または `gemini-api configure` で保存済み)。`gemini-api whoami` で確認できる。

キーが無い(`No API key found` が出る、終了コード 3)ときは、そこで止めてユーザーに設定を頼む。キーは本人が Google AI Studio で発行するものなので、自分で `configure` を実行したり、リトライを繰り返したりしない。

## コマンドの選び方

| やりたいこと | コマンド |
|---|---|
| 文章のレビュー・推敲、意見、要約、翻訳などテキスト全般 | `generate` |
| PDF・画像・音声・動画・YouTube について質問する | `analyze` |
| 音声・動画を文字起こし、字幕にする | `transcribe` |
| 画像を生成・編集する | `image` |
| テキストを音声にする | `tts` |
| 音楽を作る | `music` |
| 動画を作る | `video` |
| 調査などを長時間タスクとして委任する | `agent run --agent ... --background` |
| 約14MBを超えるファイルを渡す | `files upload --wait` → `files/<id>` を `-i` に渡す |

フラグの詳細はここに書き写していない。CLI は更新が速いので、使う前に `gemini-api <command> --help` を見るのが確実(ネットワークもキーも不要)。

## モデルの選び方

### generate(テキスト)

`-m` を毎回明示する。CLI 組み込みの既定モデルはバージョンによって変わり、意図と違うモデルで走ってしまうため。

- **`gemini-4-neon/gemini-4-carbon` が基本**。文章のレビュー・推敲、設計への意見、込み入った推論、品質が大事なものは全部こちら
- **`gemini-4-hydrogen` は軽い作業用**。短い言い換え、単純な整形や分類、機械的な抽出、ざっくりした要約、大量に繰り返す処理など、速さと安さが効く場面

文章の良し悪しを判断する仕事ではモデルの差がそのまま結果に出るので、迷ったら carbon を選ぶ。
`analyze` も中身はテキスト推論なので同じ考え方でよい。

### generate 以外

用途ごとに専用モデルがあるので、まずは CLI の既定に任せ、必要なときだけ `-m` で変える。

- `image`: 既定で十分なことが多い。文字入りの画像や高精細な出力が要るなら上位モデル、大量のラフなら軽量モデル
- `tts`: 既定が最上位。大量・速度優先なら lite 系
- `transcribe`: 既定(文字起こし専用モデル)のまま
- `music` / `video`: 既定のまま。短いクリップや試作なら軽量側を検討

その時点で選べるモデルは `gemini-api models`(オフラインのカタログ)と `gemini-api models list --all`(キーで実際に使えるもの)で確認する。カタログはバイナリに同梱されているので、新しいモデルが載っていないことがある。

指定したモデルが拒否されたら、`models list --all` で実在を確かめ、どのモデルに替えたかをユーザーに伝える。黙って別モデルに切り替えない。

## 日本語の文章をレビューする・綺麗にする

### 渡し方

本文は**ファイルで渡す**(`-i`)。長い日本語を引数に直接書くと、クォートや改行の扱いで壊れやすい。指示は位置引数、役割は `--system` に分ける。

```bash
# レビュー(指摘だけもらう)
gemini-api generate "この文章をレビューしてください。誤字脱字、文法の誤り、不自然な言い回し、冗長な箇所、論理の飛躍を、該当箇所の引用・問題点・修正案の形で挙げてください。問題のない箇所には触れなくて構いません。" \
  -i docs/article.md \
  --system "あなたは日本語の編集者です。書き手の意図と文体を尊重し、意味や事実は変えません。" \
  -m gemini-4-carbon > review.md

# 推敲(書き直した全文をもらう)
gemini-api generate "この文章を、意味と事実を変えずに自然で読みやすい日本語に直してください。見出し・箇条書き・コードブロックなどの構造はそのまま残し、直した全文だけを出力してください。" \
  -i docs/article.md \
  --system "あなたは日本語の編集者です。" \
  -m gemini-4-carbon > article.revised.md
```

ファイルになっていない文章(会話中の下書きなど)は、いったん一時ファイルに書き出すか `--stdin` でパイプする。`--stdin` の内容は位置引数のプロンプトより前に送られる。

### 頼み方のコツ

- **レビューと書き直しを分けて頼む**。「指摘して、ついでに直して」と一度に頼むと、どこをなぜ変えたのかが追えなくなる
- **文脈を伝える**。誰が読むのか(社内、顧客、技術者、一般)、媒体(README、ブログ、メール、仕様書)、文体(です・ます/だ・である)、変えてほしくない用語。これが無いと無難で平板な文章に均される
- **観点を絞る**と指摘が具体的になる。誤字脱字だけ、敬語だけ、冗長さだけ、など
- 短い一文の言い換え候補が欲しいだけなら `gemini-4-hydrogen` で足りる

### 結果の扱い

返ってきたものは提案として扱い、採るかどうかは自分で判断する。

- レビューの指摘は一つずつ自分で妥当性を見て、採るものだけ反映する。的外れな指摘や好みの問題も混ざる
- 書き直しは元ファイルを直接上書きさせず、別ファイルに受けて差分を確認する。意味が変わっていないか、数値・固有名詞・リンク・コードが落ちていないかを見る
- ユーザーには、何を採用して何を見送ったかを簡潔に伝える

## セカンドオピニオン

自分の結論を先に伝えると相手がそれに引きずられるので、材料と問いだけを渡して独立した意見をもらう。

```bash
gemini-api generate "添付の設計メモを批判的にレビューしてください。見落としているリスク、もっと単純な代替案、前提の怪しい箇所を、重要度の高い順に挙げてください。" \
  -i design.md -i src/cache.ts \
  -m gemini-4-carbon
```

- `-i` は複数指定できる。関係するファイルをまとめて渡す
- スクリーンショットやモックなど画像込みで見てほしいときは `analyze -i before.png -i after.png "..."`
- 返ってきた意見は鵜呑みにせず、自分の見解と突き合わせ、食い違う点を拾ってユーザーに示す

会話を続けたいときは、1回目を `--stream=false --jq '.id'` で実行して ID を取り、次の呼び出しに `--previous-interaction-id <id>` を付ける。CLI 自体は状態を持たないので、ID は自分で控えておく。

## ファイル解析と文字起こし

```bash
gemini-api analyze -i spec.pdf "認証まわりの要件を箇条書きで抜き出して" -m gemini-4-carbon
gemini-api analyze -i https://youtu.be/XXXX "3分以降で説明している手順をまとめて"
gemini-api transcribe -i interview.mp4 --format srt --out interview.srt
```

- `analyze` は答えだけを stdout に出す。`transcribe` はファイルに書き、そのパスを stdout に出す
- `transcribe` の形式は `md`(既定)、`text`、`json`、`srt`。話者ラベルとタイムスタンプは既定でオン
- ローカルファイルはリクエストに埋め込まれる。約14MBを超えるものは先にアップロードする(48時間で消える)

```bash
FILE=$(gemini-api files upload lecture.mp4 --wait)
gemini-api analyze -i "$FILE" "要点をタイムスタンプ付きで"
```

## メディア生成

メディア系は生成物をファイルに書き、stdout には**書き出したパスだけ**を出す。そのパスを受け取って次の作業に使う。

```bash
gemini-api image "開発者ツール用の親しみやすいロボットのマスコット、柔らかいスタジオ照明、文字なし" \
  --aspect-ratio 16:9 --image-size 2K --out ./assets/hero.jpg
gemini-api image "冬用のマフラーを足して背景を雪景色に" -i ./assets/hero.jpg --out ./assets/hero-winter.jpg
gemini-api tts -f narration.txt --voice Kore --language ja-JP --out ./assets/narration.wav
gemini-api tts "アリス: ようこそ。 ボブ: 始めましょう。" --multi-speaker "アリス=Kore,ボブ=Puck" --out ./assets/dialogue.wav
gemini-api music "製品紹介向けの落ち着いたアンビエント" --out ./assets/
gemini-api video "陽の差す工房をゆっくり進むカメラ" --aspect-ratio 16:9 --out ./assets/
```

- `--out` にディレクトリを渡すとファイル名は自動で付く。ファイル名を指定した場合でも、拡張子は実際の形式に合わせて変わる(TTS は常に WAV)。どちらの場合も、指定した名前ではなく stdout に出たパスを使う
- 画像プロンプトは、被写体・構図・光・画風・入れたくないもの(文字、透かし)を具体的に書く。見出しを載せる余白が要るならそれも書く
- 生成した画像は自分の目で確認してから使う。意図と違えば、編集(`-i` で元画像を渡す)かプロンプトの修正でやり直す
- `video` は時間がかかる。待てないときは `--async` で ID だけ受け取り、後で `gemini-api video --resume <id>` で回収する

## 長時間の調査を任せる

```bash
ID=$(gemini-api agent run "電池リサイクルの手法を調査し、出典付きでまとめて" \
  --agent deep-research-preview-04-2026 --background --jq '.id')

gemini-api agent status "$ID" --stream=false --output-format json   # 進捗と結果
gemini-api agent cancel "$ID"                                        # 中止
```

`--background` で ID だけ受け取ってすぐ戻り、自分は他の作業を進める。使えるエージェントは `gemini-api agent list` と `gemini-api agent run --help` で確認する。

## 出力を機械的に扱う

- 既定ではテキストをストリームで stdout に流す。ファイルに受けるならそのままリダイレクトでよい
- JSON で1件まるごと受けたいときは `--stream=false --output-format json`。フィールドを抜くなら `--jq '<式>'`
- `--dry-run` は通信せずに、送信されるリクエストを表示する。フラグの組み合わせに自信がないときや `--body` を組むときに先に試す
- フラグで足りない細かい指定(構造化出力のスキーマ、ツールなど)は `gemini-api <command> --schema` でスキーマを見て `--body @request.json` で渡す
- 終了コード: `0` 成功 / `1` 実行時・API エラー / `2` 使い方の誤り / `3` 認証エラー

Windows では、Bash ツール(Git Bash)でも PowerShell でも動く。上の例は Bash の書き方なので、PowerShell では行継続を `` ` `` に、変数代入を `$ID = gemini-api ...` に読み替える。

## 気をつけること

- **外部に送っている**という意識を持つ。渡したファイルの中身は Google の API に送信される。API キーや認証情報、個人情報、社外秘と分かっているものは、ユーザーに確認してから渡す
- **サーバー側の保存**。`generate` はやり取りがサーバー側に保存されるので、残したくないときは `--body '{"store":false}'` を足す(`analyze`、`transcribe`、`tts` は元から保存されない)
- **費用**。テキストは気軽に使ってよいが、動画・音楽の生成、Deep Research、大量の画像生成は高くつく。ユーザーが頼んでいないのに自分の判断で走らせない
- **Gemini の出力は材料**。レビューも調査結果も、検証してから使う。事実関係は特に確かめる
- **使ったことを伝える**。Gemini に何を頼み、どのモデルを使い、結果をどう扱ったかを、ユーザーへの報告に一言入れる
